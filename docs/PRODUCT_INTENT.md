# Redpen 제품 의도

## 1. 문제

UI를 보고 무엇을 바꾸고 싶은지는 알지만, 이를 코딩 에이전트에 정확히 설명하려면 불필요한 번역 작업이 발생한다.

- “여기”, “이 버튼”, “이만큼”, “이런 표”처럼 화면을 보면 명확한 지시가 텍스트에서는 모호해진다.
- 사용자는 F12, selector, computed style, 픽셀값 또는 컴포넌트 이름을 확인해야 한다.
- 여러 변경을 한 번에 설명하면 대상과 요구사항이 섞인다.
- 스크린샷에 자유롭게 그린 표시만으로는 어디까지가 하나의 요구사항인지, 작성이 끝났는지 알기 어렵다.
- 기존 화면의 문제점뿐 아니라 원하는 새 구조를 직접 스케치하고 싶을 수 있다.

Redpen은 사용자의 시각적 의도를 화면 좌표와 DOM 문맥이 있는 구조화된 작업으로 바꾼다.

## 2. 대상 사용자

### Primary persona

코드를 자주 열어보지는 않지만 결과 화면을 판단하고 원하는 변화를 설명할 수 있는 바이브 코더.

### Secondary personas

- 디자이너 및 디자인 엔지니어
- 프로토타입을 직접 수정하는 기획자
- UI 회귀나 개선점을 전달하는 QA
- 비개발 직군과 함께 빠르게 프론트를 수정하는 개발자

Redpen은 “코드를 모르는 사람을 위한 교육 도구”가 아니다. 사람이 이미 가진 시각적 의도를 에이전트가 사용할 수 있는 문맥으로 변환하는 도구다.

## 3. Job to be done

> 로컬에서 실행 중인 페이지를 수정하고 싶을 때, 코드나 CSS 값을 찾지 않고 화면에 직접 표시해 여러 요구사항을 정확히 전달하고 싶다.

## 4. 가치 제안

> Don't describe the UI. Draw it.

한국어 제품 문구:

> 말로 설명하기 힘든 UI 수정, 화면에 직접 그려서 에이전트에게 맡기세요.

## 5. 제품 원칙

### 5.1 Visual first

사용자는 화면에 직접 표시한다. 텍스트는 시각적 지시가 애매할 때 의도를 보완하는 역할이다.

### 5.2 DOM is invisible plumbing

DOM과 selector는 정확도를 높이기 위한 내부 문맥이다. 기본 UI에 개발자 패널처럼 노출하지 않는다.

### 5.3 Explicit completion

Redpen은 “그림을 다 그렸는지” 추측하지 않는다. 사용자가 `N개 지시 제출`을 누르는 순간이 완료 신호다.

### 5.4 Color groups intent

색은 단순 스타일이 아니라 하나의 Instruction Group을 나타낸다. 같은 색으로 그린 여러 표시는 같은 요구사항에 속한다.

색만을 식별자로 사용하지 않는다. 모든 그룹은 번호와 영구 ID를 가지며 화면에도 색과 번호를 함께 표시한다.

### 5.5 Model agnostic

Redpen은 이미지 해석이나 코드 수정을 수행하지 않는다. 작업 번들을 만들어 로컬 파일, CLI, MCP를 통해 네이티브 에이전트에 전달한다.

### 5.6 Local and private by default

페이지, 이미지, DOM 정보, 브라우저 프로필은 로컬에서 처리한다. 외부 전송은 MVP 범위가 아니다.

### 5.7 Fast path over power features

핵심 경로는 30초 안에 이해할 수 있어야 한다.

```text
페이지 열기 → 화면 고정 → 지시 그룹별 표시 → 제출
```

## 6. 핵심 사용자 흐름

### 6.1 세션 시작

1. 사용자가 “이 페이지 수정할 거야. Redpen 열어봐”라고 요청한다.
2. 에이전트 또는 사용자가 `redpen open <url>`을 실행한다.
3. Redpen 전용 브라우저가 열리고 세션 상태는 `browsing`이 된다.

### 6.2 화면 선택

1. 사용자가 페이지를 클릭하고 스크롤하며 원하는 상태를 만든다.
2. `이 화면 표시하기` 버튼을 누른다.
3. Redpen은 같은 시점의 viewport screenshot과 visible DOM index를 캡처한다.
4. 별도의 annotation 화면이 열리고 상태는 `annotating`이 된다.

### 6.3 여러 지시 작성

1. 최초 그룹 `#1`이 자동 생성되고 첫 색이 배정된다.
2. 선택된 그룹 색으로 펜, 화살표, 사각형, 원, 텍스트, mask를 그린다.
3. 여러 떨어진 표시는 같은 그룹에 속할 수 있다. 각 표시 군집에 동일한 번호 badge를 표시한다.
4. 우측 카드에 선택적으로 한 줄 설명을 입력한다.
5. `새 지시`를 누르면 다음 번호와 색이 생성된다.

### 6.4 제출

1. `N개 지시 제출` 버튼을 누른다.
2. 비어 있는 그룹만 경고한다. 설명이 없는 그룹은 허용한다.
3. 작업 번들을 원자적으로 저장하고 상태를 `submitted`로 바꾼다.
4. 대기 중인 CLI/MCP 호출에 작업 경로와 요약을 반환한다.

### 6.5 에이전트 작업 및 검토

1. 에이전트가 그룹별 이미지, 설명, DOM target을 읽는다.
2. 에이전트가 상태를 `working`으로 바꾼다.
3. 기본 동작은 구현 계획 작성이다. 사용자가 명시하면 코드를 수정한다.
4. 구현 후 동일 세션을 `review`로 열어 결과 화면을 다시 확인한다.
5. 사용자는 승인하거나 새 revision에 추가 표시를 남긴다.

## 7. Instruction Group UX

한 Visual Task에는 여러 Instruction Group이 존재한다.

```text
🔴 #1  헤더 간격과 버튼 위치 변경
🔵 #2  이 영역을 직접 그린 표 형태로 재구성
🟢 #3  아래 안내 문구 삭제
```

### 동작 규칙

- 그룹 카드를 선택하면 pen color가 자동으로 전환된다.
- 색은 identity hint이며 `groupId`가 canonical identity다.
- 색상은 고대비 팔레트에서 자동 배정한다.
- 팔레트가 순환하더라도 번호는 재사용하지 않는다.
- 같은 그룹에 여러 mark와 여러 DOM target을 연결할 수 있다.
- 같은 그룹이 여러 화면 영역에 걸치면 badge를 각 군집에 반복 표시한다.
- 설명 카드 border, badge, canvas stroke는 같은 색을 사용한다.
- 색에 `삭제`, `추가` 같은 동작 의미를 고정하지 않는다. 색은 오직 그룹 구분에 사용한다.

## 8. 직접 그리는 새 UI

사용자는 기존 UI를 지적하는 것뿐 아니라 원하는 결과를 그릴 수 있다.

- 표의 행과 열을 직접 그리기
- 카드, 버튼, 메뉴의 대략적인 위치와 크기 그리기
- 기존 요소를 mask로 가리고 새 구조 덧그리기
- 빈 영역에 새 컴포넌트를 그리고 화살표로 삽입 위치 연결하기
- text tool로 정확한 label이나 column name 입력하기

이 경우 기존 DOM target이 없을 수 있다. Redpen은 mark의 bounding box, destination point, 가장 가까운 container를 저장하며 최종 해석은 에이전트가 수행한다.

## 9. MVP 범위

### 포함

- localhost/127.0.0.1 페이지
- 데스크톱 Chromium 한 종류
- 현재 viewport 캡처
- 단일 사용자, 단일 로컬 머신
- 한 세션의 한 화면과 여러 지시 그룹
- pen, arrow, rectangle, ellipse, text, mask, erase, undo/redo
- 그룹별 색, 번호, 설명
- visible DOM grounding
- 로컬 task bundle
- human-readable CLI와 `--json` 출력
- stdio MCP adapter
- Codex/Claude용 공용 Skill 본문

### 비포함

- Redpen 내부 LLM 또는 AI API
- 자동 코드 수정
- CSS/DOM inspector UI
- 임의 웹사이트 캡처
- 사용자 브라우저 프로필 직접 재사용
- 모바일 브라우저 및 실제 기기
- 브라우저 확장 프로그램
- 다중 사용자 협업과 클라우드 동기화
- iframe과 shadow DOM 내부의 완전한 grounding
- 소스맵을 통한 DOM→React source 자동 역추적
- 픽셀 단위 디자인 보장

## 10. 성공 기준

### 사용성

- 처음 본 사용자가 문서 없이 페이지를 열고 세 가지 지시를 제출할 수 있다.
- 지시 생성에 selector, CSS 값, 파일명 입력이 필요하지 않다.
- 단순 요청은 설명 없이 그림만으로 제출 가능하다.

### 정확성

- 원본 화면과 annotation layer가 분리 저장된다.
- 모든 mark는 정확히 하나의 Instruction Group에 속한다.
- 화면 badge와 sidebar card, JSON group ID가 일치한다.
- 캡처와 DOM index의 좌표계 및 시점이 일치한다.
- 각 그룹에 교차하거나 인접한 DOM target이 제공된다.

### 호환성

- CLI만으로 전체 세션 수명주기를 조작할 수 있다.
- Codex와 Claude가 동일한 task bundle을 읽을 수 있다.
- MCP 없이도 파일 경로와 CLI JSON만으로 작업을 인계할 수 있다.

## 11. 제품이 피해야 할 방향

- “더 정확하게 만들기”를 이유로 사용자가 selector를 선택하게 하지 않는다.
- 화면에 개발자 도구와 같은 복잡한 패널을 추가하지 않는다.
- 자유로운 그림을 미리 정의된 gesture 문법으로 강제하지 않는다.
- 모델이 알아서 판단할 수 있는 의도를 긴 양식으로 입력하게 하지 않는다.
- 색에 작업 의미를 과도하게 부여하지 않는다.
- 캡처 전 전체 DOM이나 입력값을 디스크에 무차별 저장하지 않는다.
