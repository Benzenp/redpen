### 만든 것

- pnpm workspace scaffold: `package.json`, `pnpm-workspace.yaml`, `tsconfig.base.json`, `.gitignore`
- `apps/cli` 패키지: `playwright`, `tsx`, `typescript`, `@types/node` 의존성, Windows 대상 Chromium 브라우저 바이너리 설치
- `fixtures/frontend/index.html`: 스크롤, 뷰포트 밖 element, `display:none` element, password input, `data-testid`를 포함한 결정론적 E2E fixture 페이지
- `apps/cli/src/spike/dom-index.ts`: `DomIndexResult`/`DomCandidate` 타입과 좌표 기반 `findCandidateAtPoint` (Node 측)
- `apps/cli/src/spike/dom-index-browser.js`: 브라우저 컨텍스트에서 `page.evaluate`로 그대로 실행되는 순수 JS visible DOM collector (민감 데이터 미수집)
- `apps/cli/src/spike/capture-spike.ts`: persistent Chromium 실행 → Shadow DOM `Mark this screen` 버튼 주입 → 클릭 시 동일 tick screenshot + DOM index 캡처 → 좌표→DOM 역매핑 검증 → 스크롤 후 재검증 → password 값 미수집 검증. 10개 자동 assertion을 모두 포함.

### 검증

`pnpm --filter @redpen/cli run spike:capture` 실행 결과 10/10 통과:

- Shadow control이 클릭 후 정상적으로 숨겨짐
- `save-button`이 top 캡처에서 수집되고 클릭 좌표가 정확히 해당 element로 resolve
- `display:none`, 화면 밖(5000px) element가 index에서 제외됨
- 스크롤(y=1100) 후 재캡처에서도 `price-card`가 새 좌표로 수집·정확히 resolve — capture-time 좌표 일치 검증
- `scroll.y` 메타데이터가 실제 스크롤 값과 일치
- password input의 `value`는 어떤 직렬화 결과에도 나타나지 않지만, element 존재 자체는 candidate로 남음(redaction 원칙 검증)

산출물: `apps/cli/.spike-output/{screenshot-top.png, screenshot-scrolled.png, dom-index-top.json, dom-index-scrolled.json, report.json}`.

### 발견한 제약 (docs/IMPLEMENTATION_PLAN.md에 기록함)

- esbuild/tsx로 컴파일된 함수를 문자열로 직렬화해 `page.evaluate`에 넘기면 컴파일러가 삽입한 `__name()` 헬퍼가 브라우저 컨텍스트에 없어 `ReferenceError`가 발생. 해결책으로 브라우저 주입 로직을 별도 순수 untranspiled `.js` 파일로 분리하고 파일 내용을 문자열로 읽어 `page.evaluate(sourceText)` 방식으로 실행하도록 변경. 이후 daemon 구현 시에도 이 분리 원칙을 유지해야 함.
- tldraw 자체는 이번 spike에서 검증하지 않음 (Phase 0 목표가 capture/grounding 가정 검증이었기 때문). tldraw 채택 판단은 Phase 2 시작 시 별도로 수행 필요.
- `redpen open <url>`의 실제 localhost dev-server 대상 열기는 이번 spike에서 `file://` fixture로 동일 원리만 검증했고, 실제 HTTP localhost 대상 확인은 Phase 4 CLI에서 재검증 필요.
- macOS/Linux 교차 확인은 미실시 (현재 워크스테이션이 Windows이므로 Windows 경로만 통과 확인).
